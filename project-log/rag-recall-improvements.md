# RAG Recall 提升记录

这份记录只收录会影响检索 Recall、Precision 或端到端语义评估的较大改动。
每次记录包含基线、改动、验证方式、结果和 Git commit，避免把不同语料快照的指标混在一起。

## 指标口径

- `Recall@K`：候选证据是否覆盖预先定义的答案证据，属于检索层指标。
- `Context Recall / Context Precision`：RAGAS 对回答、参考答案和上下文的语义评估，不等价于端到端答案准确率。
- 所有远程数据库结果必须注明 corpus snapshot 的行数、股票数和时间范围。

## RAG-R1：加权 Hybrid 接入线上链路

- 日期：2026-08-13
- commit：`f5e1cfe`
- 改动：中文金融同义词扩展；数字、股票代码和中文字符增强分词；候选池至少 20 条；BM25 2× 加权 RRF；RAGAS 使用 DashScope `text-embedding-v3`，Answer Relevancy 采用兼容当前模型 API 的 `n=1`。
- 验证：项目测试 `228/228` 通过；10 条远程 DB 样本的 RAGAS 消融。
- 结果：最佳组合 `hybrid_scoped_bm25_2x` 的 Context Recall `0.6000`、Context Precision `0.6224`、Faithfulness `0.9347`；BM25 scoped 的 Context Precision `0.6905`。
- 结论：排序优化有效，但部分答案事实根本不在当前新闻库，下一步必须补充语料。

## RAG-R2：评测股票纳入生产刷新列表

- 日期：2026-08-13
- 改动：将 10 条评测股票统一纳入 `EVAL_STOCKS`，并与生产 `WATCH_LIST` 合并去重；新增 `scripts/refresh_news_index.py`，支持通过 SSH 隧道增量刷新、指定股票、刷新全部已有股票和 dry-run。
- 刷新前快照：远程 `news_vectors` 约 `1,370` 条、约 `171` 只股票；最近 7 天约 `127` 条；部分评测股票最新日期停在 2026-08-07 至 2026-08-11。
- 运行结果：待刷新完成后补充新增条数、快照和 Recall/RAGAS 对比。
- 预期：优先补齐 601138、002415、300124、600487 等评测股票的最新新闻，减少“答案事实不在库”的缺口。
- 阶段结果：601138 新增 10 条；300124 新增 10 条；600487 新增 8 条；正确代码 002415 新增 9 条。合法新增合计 37 条，合法语料预计从 1,370 增至 1,407 条。
- 最终结果：22 只股票再次增量刷新时，300124 新增 1 条；远程有效语料快照为 `1,408` 条、`171` 只合法股票，较刷新前 `1,370` 条净增 `38` 条。
- 刷新后检索诊断：`bm25_scoped_expanded` 从 `0.5869` 提升到 `0.6355`（+4.86 个百分点）；`hybrid_scoped_bm25_2x` 从 `0.6427` 到 `0.6426`，基本持平。
- 刷新后 RAGAS：`bm25_scoped_expanded` 的 Context Recall 从 `0.5167` 提升到 `0.5667`，Context Precision 从 `0.6905` 提升到 `0.7540`；`hybrid_scoped_bm25_2x` 的 Context Recall 从 `0.6000` 降到 `0.5333`，Context Precision从 `0.6224` 降到 `0.6030`。
- 结论：补充语料改善了 601138、300124、600487 的 BM25 证据覆盖，但新增近义新闻给 Dense/Hybrid 带来噪声。当前快照应优先采用股票范围内 BM25，而不是直接沿用 Hybrid 2×。

## RAG-R3：增量刷新去重前置与批量写入

- 日期：2026-08-13
- 原因：原实现会对数据库中已经存在的新闻重复计算 768 维向量，并通过 SSH 隧道逐条执行 INSERT；13 只已有股票刷新耗时超过 6 分钟且全部新增为 0。
- 改动：入库前先按确定性新闻 ID 查询已存在记录，只对新增新闻生成 embedding；每只股票使用一次批量 INSERT，并继续通过 `ON CONFLICT DO NOTHING` 处理并发去重。
- 安全性：不删除、不覆盖历史记录；只减少无效 embedding 和数据库往返。
- 运行结果：旧实现刷新 13 只零新增股票超过 6 分钟；新实现刷新 22 只股票约 100 秒，其中 20 只重复股票在 embedding 前直接跳过，仅对 1 条新增新闻执行编码和批量写入。
- 纠错：PowerShell 会把未加引号参数中的 `002415` 转成 `2415`；刷新 CLI 现对纯数字代码统一执行 6 位左侧补零。误写的 10 条 `2415` 记录将在确认后删除并以 `002415/海康威视` 重新增量写入。
- 隔离：远程删除未获安全授权，因此 10 条 `2415` 暂时保留；全局检索、远程评测和后续全量刷新均过滤/规范化为合法 6 位代码，错误记录不参与指标计算。

## RAG-R4：索引新闻正文

- 发现：当前 Eastmoney 接口同时返回新闻标题与新闻内容，但索引只保存标题；很多金额、业绩、AI 需求、人员任职等答案事实只存在于新闻内容中。
- 计划：在保持标题稳定 ID 的前提下，将正文摘要、来源和链接加入 `full_text`，并只在新文本信息量更大时更新旧记录及 embedding。
- 验证要求：正文富化前后分别保存有效语料快照，并比较 BM25 scoped、Hybrid 和 RAGAS；若 Precision 明显下降则增加正文长度上限和字段权重。
- 运行过程：首轮已富化 18 只共 180 条，续跑后 600487 再富化 10 条；000002、000333、601012 因源接口同批重复标题触发 UPSERT 冲突并自动回滚。现已在批量写入前按稳定新闻 ID 去重，重复标题优先保留正文更长的版本。
- 最终语料：22 只股票共富化 217 条正文；远程总行数保持 1,418，合法语料保持 1,408，没有新增重复记录。
- 检索诊断：相对标题刷新快照，BM25 scoped `0.6355 → 0.6624`，Dense scoped `0.5021 → 0.5363`，Hybrid `0.5780 → 0.6003`，Hybrid 2× `0.6426 → 0.6565`。
- RAGAS 反例：直接返回完整正文时，BM25 Context Recall `0.5667 → 0.5000`、Context Precision `0.7540 → 0.6547`；Hybrid 2× 为 Recall `0.5000`、Precision `0.5193`。说明正文提升了召回排名，但整段注入制造了上下文噪声，不能直接作为最终策略。

## RAG-R5：查询相关证据句压缩

- 日期：2026-08-13
- 改动：完整正文继续用于 BM25/Dense 排名；返回给生成模型和 RAGAS 的上下文只保留标题、与 query 重合度最高的 1–2 个证据句、来源及链接，长度上限 360 字符。
- 目标：保留正文带来的事实覆盖，同时恢复 Context Precision，避免 10 条长正文挤占上下文窗口。
- 运行结果：待固定 10 题检索诊断与 RAGAS 完成后补充。
- 结果：关键词诊断 BM25 scoped `0.6507`、Hybrid 2× `0.6448`；RAGAS BM25 Recall/Precision 为 `0.5333/0.5936`，Hybrid 2× 为 `0.5333/0.5988`。优于整段正文的部分指标，但未超过标题快照。
- 确定性生成答案事实覆盖率：标题 BM25 `0.6009`、完整正文 BM25 `0.5715`、证据句 BM25 `0.5558`。因此证据句保留为语义 fallback，不作为当前主链默认上下文。

## RAG-R6：股票范围内标题 BM25 优先

- 日期：2026-08-13
- 改动：在线检索新增无需 embedding 的 30 天股票范围标题候选池（上限 500）；完整候选集执行金融词扩展 BM25，语义检索只在词法结果不足 Top-K 时补位。
- 依据：标题快照的 BM25 scoped 在当前 10 题上同时取得更高的 RAGAS Context Recall `0.5667`、Context Precision `0.7540` 和确定性答案事实覆盖率 `0.6009`；优于 Hybrid 2× 与正文/证据句方案。
- 可观测性：trace rerank method 记录为 `scoped_title_bm25_semantic_fallback`，并增加 `lexical_candidate_count`。
- 效率：执行顺序改为 BM25 先行；只有词法命中不足 Top-K 时才调用 pgvector/embedding 补位，明确问题可完全跳过 Dense 推理。

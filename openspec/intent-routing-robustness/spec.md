# 意图路由鲁棒性与评测增强

状态：已实施

## 背景

四分类 fastText 的历史验证集只有 48 条训练、12 条验证；16 条端到端
smoke 集主要覆盖固定规则。两者都可用于回归或起始基线，不能推断线上用户
分布下的准确率。特别是多股票、错别字、简称、回测时间窗缺失和交易措辞，
若被静默归到单一股票或普通分析路径，会产生比普通分类错误更高的风险。

## 目标

1. 保留四个顶层意图；复合任务仍是编排元数据，不增加第五个 fastText 标签。
2. 对可确定的本地名称、唯一简称和少量高频错别字采用确定性修正，避免把
   可安全处理的请求无谓交给 LLM。
3. 对当前单股票任务契约不能表达的多股票操作请求，拒绝静默选择第一只股票，
   改为澄清。
4. 回测任务增加 `backtest_window` 槽位；未提供时间窗时保留请求和任务图，
   但标记 `blocked_missing_slots`，供上层发起澄清。
5. 新增候选级分桶评测，分别报告澄清、高风险路由、缺失槽位和各桶端到端结果。

## 安全约束

- `trade_action` 始终 `requires_confirmation=true`，且没有证券代码时也要标为
  缺失槽位；它绝不变成经纪商执行权限。
- 两个或以上已验证股票代码出现在操作性请求中时，顶层结果必须为澄清，
  并记录 `multiple_stock_references_require_clarification`。
- 公司简称只在本地字典中唯一且不属于行业泛词时解析；例如“半导”不能因为
  恰好是某只股票名称后缀而绑定股票代码。
- 候选集是项目作者构造的压力样例，不是脱敏生产日志，也不能用于简历或线上
  准确率声明。

## 评测协议

数据集 `data/intent/eval_robustness_candidate_v1.jsonl` 覆盖：简称与无代码名称、
错别字、分析面、多股票、回测时间窗、缺失信息澄清、高风险交易、复合任务和
讨论硬负例。

评测器除既有意图/槽位/任务图指标外，新增：

- `clarification_precision`、`clarification_recall`、`clarification_f1`；
- `high_risk_route_precision`、`high_risk_route_recall`、`high_risk_route_f1`；
- `required_missing_slots_exact`；
- `bucket_metrics.*.end_to_end_exact`。

候选集必须在清单中固定字节哈希、规则快照和待独立复核状态。只有加入独立
审阅的真实或合规脱敏用户请求、冻结后与训练集隔离，才可以升级为 production
级质量结论。

## 非目标

- 不将 21 条候选集的结果宣传为生产 macro-F1、线上误路由率或简历指标。
- 不为多股票问题伪造批量分析能力；批量实体契约和逐股票任务图需要单独设计。
- 不重新训练或扩大 fastText 后直接宣称泛化提升；先获取独立审阅数据再比较。
